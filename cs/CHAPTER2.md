# 컴퓨터 구조


## 컴퓨터가 이해하는 정보

---
~~~
1. 데이터
    * 0과 1로 숫자 표현하기 ex) 정수, 실수
    * 0과 1로 문자 표현하기

2. 명령어 
    * 명령어의 종류
    * 명령어의 사이클

명령어를 이해하고 실행하는 주체 -> CPU 입니다.
따라서 CPU 종류에 따라, 명령어 종류와 처리 양상이 달라집니다.
~~~

## 컴퓨터의 핵심 부품

---
~~~
1. CPU(주요 구성 요소) - 빠른 명령어 처리를 위한 기술

2. 메모리와 캐시 메모리 - RAM, 엔디안(메모리가 데이터에 저장되는 순서), 캐시 메모리

3. 보조기억장치 - RAID(보조기억장치를 구성하는 기술)

4. 입출력장치 - 입출력기법
~~~

### CPU

---
**주요 구성 요소**
1. ALU(산술논리연산장치) - 연산을 수행할 회로로 구성되어 있는 일종의 계산기입니다.(명령어를 실질적으로 연산하는 요소입니다.)
2. CU(제어장치) - 제어 신호란 부품을 작동시키기 위한 신호를 말합니다. ex) 메모리를 향해 제어신호 -> 메모리 작동
3. 레지스터 - CPU 내부의 작은 임시 저장장치입니다. 데이터와 명령어를 처리하는 과정의 중간값을 저장합니다.(각기 다른 이름과 역할을 가지고 있습니다.)

* 워드란 -> CPU 가 한 번에 처리할수 있는 데이터의 크기를 의미합니다.


> 가장 중요한 요소는 레지스터 입니다. 명령어가 레지스터에 저장되므로, 레지스터 관찰 -> 실행 과정 파악이 가능합니다.

### 메모리와 캐시 메모리 - 휘발성

---
* 메모리는 현재 실행 중인 프로그램을 구성하는 데이터와 명령어를 저장하는 부품입니다.
* 메인 메모리 - RAM, ROM 이 있습니다.
* 주소값을 통해 명령어와 데이터에 접근할 수 있습니다.


* 캐시 메모리는 더 빨리 메모리 값에 접근하기 위해 사용하는 저장장치입니다. 
* CPU 와 메모리 중간 개념입니다.

### 보조기억장치 - 비휘발성

---
* 보관할 프로그램을 저장하는 역할을 합니다.
* **RAID** 기술이 사용됩니다.
* CD-ROM, DVD, 하드디스크 드라이브 등이 있습니다.

### 입출력장치

---
* 컴퓨터 외부에 연결되어 컴퓨터 내부와 정보를 교환하는 장치를 말합니다.
* 입력장치 - 마우스, 키보드
* 출력장치 - 스피커, 모니터, 프린터

> 보조기억장치 + 입출력장치 = 주변장치 라고 통칭하기도 합니다.

### 메인보드와 버스 구조

---
> 메인보드[CPU, 메모리, -----시스템 버스 ---]--보조기억장치, 입출력장치

### 저장장치의 계층구조

---
~~~
CPU에 가까움                       멈
빠름                              느림

레지스터 - 캐시 메모리(L1, L2, L3 캐시) - 메모리 - 보조기억장치

작음                              큼
비쌈                              저렴
~~~

## 컴퓨터가 이해하는 정보

---

### IEEE 754 부동소수점 규칙

---
* 0.1 + 0.2 != 0.3
* 컴퓨터는 10진수를 정확하게 저장하지 못합니다. -> 따라서, 0.1, 0.2 와 같은 소수는 컴퓨터 내부에서 이진법으로 저장되지만, 정확하게 나타낼 수 없어 근사값으로 저장됩니다.
* [부호] + [지수] + [가수] 형식으로 저장됩니다.


* 자바에서 실수를 다루는 방법
~~~
1. 실수는 직접 비교하지 않고 오차 허용 범위를 줘서 비교함

double a = 0.1 + 0.2;
double b = 0.3;

if (Math.abs(a - b) < 1e-9) {
    System.out.println("거의 같음");
}


2. 정확해야 할 계산은 BigDecimal을 사용

BigDecimal a = new BigDecimal("0.1");
BigDecimal b = new BigDecimal("0.2");
BigDecimal sum = a.add(b);

System.out.println(sum.equals(new BigDecimal("0.3")));  // true
~~~

### 데이터 - 0과 1로 문자 표현하기

* 문자집합이란? 컴퓨터가 이해할 수 있는 문자의 모음입니다.
* 문자 인코딩 -> 0, 1로 변환하는 것입니다.
* 문자 디코딩 -> 사람이 이해할 수 있는 문자로 변환하는 것입니다.


**EUC-KR(한글 인코딩)**
* 아스키코드를 통해 한글을 표현할 수 없습니다. -> 이를 해결하기 위해 ECU-KR 이 등장했습니다.
* 2바이트 - 16진수로 나타낼 수 있습니다.
* 총 2350 개의 한글 단어를 나타낼 수 있습니다.

**유니코드**
* 여러 국가의 언어나 이모티콘 등을 표현할 수 있는 통일된 문자 집합을 말합니다.
* '쀓', '똚' 과 같은 글자는 변환할 수 없습니다(아스키 코드 / EUC-KR로 나타낼 수 없음.) -> 이를 해결하기 위해 **유니코드**가 등장했습니다.
~~~
아스키코드 / EUC-KR -> 글자에 부여된 값을 인코딩 값으로 삼음
유니코드 -> 다양한 방법으로 인코딩
~~~

* UTF-8, UTF-16 같은 인코딩 방식이 존재합니다(가변 길이 인코딩)
> UTF-8, UTF-16은 유니코드 문자에 부여된 값을 인코딩하는 방식을 말합니다.

**base64 인코딩**
* 문자뿐 아니라, 이진 데이터까지 변환할 수 있는 인코딩 방식입니다.
* 이미지 등 단순 문자 이외의 데이터까지 모두 아스키 문자 형태로 표현할 수 있습니다.


### 명령어

---
* 수행할 동작 - 수행할 대상(데이터 자체 or 데이터의 위치)으로 이루어져 있습니다.
**수행할 동작 = 연산코드 / 수행할 대상 = 오퍼랜드**
~~~
    기계어         어셈블리어
0101 0101 -------> push rbp
0101 1101 -------> pop rbp
~~~

**🧠 명령어 수행 사이클 정리**

CPU가 명령어를 수행할 때는 여러 단계의 **사이클(Cycle)** 을 거칩니다. 각각의 명령어 종류에 따라 사이클이 달라질 수 있습니다.

---

📌 기본 사이클 종류

| 사이클 이름        | 설명 |
|-------------------|------|
| **인출 사이클 (Fetch Cycle)** | 메모리에서 **명령어를 읽어오는 단계** |
| **간접 사이클 (Indirect Cycle)** | 명령어가 가리키는 주소가 **또 다른 주소를 가리킬 때**, 그 주소를 **추가로 해석**하는 단계 |
| **실행 사이클 (Execute Cycle)** | 명령어에 따라 실제 연산, 메모리 접근 등을 **실행하는 단계** |
| **인터럽트 사이클 (Interrupt Cycle)** | 인터럽트가 발생했을 때 이를 **처리하는 단계** |

---

✅ 명령어 형태에 따른 사이클 흐름

1. 즉시 주소 (Immediate Addressing)

- 예시: `LOAD #5`
- 의미: 명령어에 데이터 값 **5가 직접 포함됨**
- 🔁 사이클 흐름:  
  `인출 사이클 → 실행 사이클`

---

2. 직접 주소 (Direct Addressing)

- 예시: `LOAD 1000`
- 의미: 메모리 **1000번지**에서 값을 가져옴
- 🔁 사이클 흐름:  
  `인출 사이클 → 실행 사이클`

---

3. 간접 주소 (Indirect Addressing)

- 예시: `LOAD @500`
- 의미: 500번지에 저장된 값(예: 1000)을 주소로 사용 → 최종적으로 1000번지에 있는 값을 가져옴
- 🔁 사이클 흐름:  
  `인출 사이클 → 간접 사이클 → 실행 사이클`

---

🧾 요약 표

| 명령어 형태        | 예시         | 사이클 순서                         |
|-------------------|--------------|-------------------------------------|
| 즉시 주소         | `LOAD #5`    | 인출 → 실행                         |
| 직접 주소         | `LOAD 1000`  | 인출 → 실행                         |
| 간접 주소         | `LOAD @500`  | 인출 → 간접 → 실행                  |

---

📎 참고

- `간접 주소`만 추가적으로 메모리 접근이 **한 번 더 필요**함
- 그 외는 명령어만으로 필요한 주소에 도달할 수 있기 때문에 `간접 사이클`은 생략됨
